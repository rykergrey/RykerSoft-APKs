# Technical Specifications

## Platform & Requirements

- **Target OS**: Android 7.0+ (API Level 24+ typical Godot export floor); Windows x86_64
- **Engine**: Godot 4.7 (Mobile / Vulkan Mobile export)
- **Package ID**: `com.rykersoft.freeballing`
- **versionCode / versionName**: `46` / `1.0.30`
- **Architectures**: Android `armeabi-v7a`, `arm64-v8a`; Windows `x86_64`
- **Windows packaging**: Portable Godot release EXE with embedded PCK; file/product version `1.0.30.0`
- **Android release signer SHA-1**: `80BD2A1BBC461F86B50F6C569692A6C7BE010F54`
- **Android release signer SHA-256**: `AEC0A0690D2D2F288739D41FBF089F776FE5BEE6385033383A4BC1132BF0587E`

## Architecture

- **Scenes / scripts**: GDScript game board, shooter, pegs, UI home/editor overlays
- **Home UI**: Mobile has independent Home, Community, More, and Profile destinations with saved route state. Home and Community offer a selected-board gallery and a searchable list with real board thumbnails, category/favorites/recent filters, and sorting of loaded entries. The shared thumbnail renderer serializes work, bounds pending requests and its texture cache, and shows an unavailable state when geometry cannot be loaded. AccurateLevelPreview uses a non-playing GameBoard: mobile renders one frozen snapshot per selection; desktop animates unless hidden by an overlay or unfocused. Resizing across the desktop breakpoint preserves board selection, source, loaded community pages, and browse state.
- **Branding and chrome**: Shared transparent supplied SVG `ArcadeBrand` with layered cyan-and-magenta lettering, mipmapped sampling, and an alpha-silhouette shadow. Mobile Home and gameplay share a 104 px header footprint. Square-corner paper controls and panels use retained shadows; the mobile board has a soft perimeter cast. The mobile surround is a static fill matched to the selected level rail color and excludes the live cabinet. Desktop Home retains the editor `HOME` ambient preset.
- **Physics**: GodotPhysics2D (ported feel from the Matter.js web client); energy-neutral anti-loop redirects; no scripted soft-bounce boosts on fixed pegs; any sustained contact with a SOLID piece triggers its wall-clock escape/ghost timer, including arches and rotated or concave shapes
- **Scoring**: Central fixed-value `ScoringRules` table; bumper hits accumulate across every multiball in one shot, pay 50 per hit, heat from hit 5, and overload at hit 10 for a 500 bonus; bonus pegs are points-only; capped per-ball gutter payout; isolated multiball run totals. Level-specific gutter multipliers and well colors refresh the five physical capture areas whenever a board loads.
- **Bumper lifecycle**: One shared per-shot hit dictionary drives heat from hit 5 and critical sparks; overloaded bumper nodes and spin-group colliders are temporarily disabled, then materialize in a staggered sparkle sweep after the complete shot including multiballs
- **Aiming**: Wall-clock launcher presentation; collision-free trajectory overlay; per-frame pointer sampling while charging
- **Hit-stop**: Short real-time freeze that restores gameplay pace immediately when its budget expires
- **Motion**: `MotionUtils` + versioned `objectMotions` on `LevelData` for foreground peg slide/wobble/spin/scale profiles, including shared-pivot grouped orbit motion and non-destructive live editor preview
- **Editor**: Full authoring is desktop-only; Android editor actions show an introduction. Wide desktop uses a professional studio shell with slim left tool rail, top persona bar (Foreground / Background), contextual property bar, and right Studio dock (Color, Swatches, Layers with real-time search and paging, Motion, Quick Select, Appearance). Features flow path deterministic spacing and axis locks, continuous numeric editing with coalesced undo/redo, centered 10/15/20/30/40 px grids, stable formation previews, full-silhouette rail containment, and lossless full-model undo/redo history
- **Navigation and pause**: Back/Escape dismisses nested popups and Home overlays first, returns secondary mobile destinations to Home, then offers exit confirmation. Gameplay pauses/resumes on Back/Escape and pauses on focus loss/backgrounding. SceneTree pause freezes the simulation; the modal remains interactive. The mobile preview-to-game transition retains the source viewport and logo without a screenshot readback; gameplay stays frozen until handoff, and interrupted transitions open Pause. Reduced motion uses a short dissolve. Automatic attract-mode demos run only on desktop. Keyboard aiming/charging and optional untimed practice complement touch/mouse.
- **Audio**: Material sample banks (standard / bumper / armored / multi) plus BGM; stereo pan by hit X. Authored sample imports, file choices, and pitches remain unchanged; fixed-size pools and per-frame voice budgets never retune or replace those sounds. Wall hits and generic non-scale feedback events stay silent because they have no dedicated authored samples. Android preloads music asynchronously, keeps one looping MP3 decoder active, and omits the desktop collision-bus reverb.
- **Performance**: `PlatformPerformance` renders mobile CanvasItems at native resolution, keeps gameplay physics at 60 Hz with interpolation, and caps Android presentation at a deterministic 60 FPS. Mobile starts in `BALANCED_60` and enters `SAFE_60` only after sustained slow-frame pressure; the tiers bound trail history, particle density, ambient shapes, collision decoration, arc detail, refraction, and antialiasing while desktop defaults to `FULL`. Both platforms allow manual Full/Balanced/Safe preferences. Desktop now samples frame percentiles too; unfocused rendering is capped at 15 FPS and excluded from quality adaptation. Ambient nodes stop processing while hidden or inactive and discard suspended score-wave work. The render-animated launcher opts out of physics interpolation to avoid double-sampling. Grouped motion sampling reuses dictionaries; ball trails and CPU particles use bounded pools and linear compaction.
- **Name input**: Local high scores use three reusable letter cards; public usernames retain five cards and support one-to-five-letter A–Z names through blank cards. Physical `InputEventScreenTouch` / `InputEventScreenDrag` routing ignores emulated duplicates, uses unscaled screen deltas, magnetic 180 px steps, and velocity-based one-to-five-letter flicks. Each uninterrupted touch direction is limited to five letter transitions, including a release flick. Reversing a held touch resets that directional budget and residual movement; stale velocity cannot flick back in the previous direction.
- **Authentication**: Optional Google sign-in uses a Godot v2 Android plug-in with Android Credential Manager on Android. Windows opens a project-authorized localhost page in the system browser and uses Firebase's official browser SDK with in-memory persistence; the page returns only the Firebase UID and session tokens to the game over a state-verified loopback callback. Google email, name, avatar, provider tokens, and OAuth client secrets are never published or persisted by the game.
- **Windows session security**: Session-only by default. Opt-in remember-sign-in encrypts the Firebase refresh token using CurrentUser Windows DPAPI, invoked through a fixed PowerShell helper with private stdio pipes. Tokens do not appear in command arguments or plain save JSON. Sign-out deletes the encrypted file. Failure falls back to guest/session-only use. Windows hardware verification is a release check.
- **Public identity**: Unique uppercase A–Z usernames are one to five letters, atomically reserved in Firestore, and may change once every 30 days. Retained reservations prevent old names from being claimed by another UID.
- **Persistence**: Local saves keep customs, preferences, profile stats, and local player initials limited to three letters separate from the authenticated public username. Existing longer local player preferences use their first three A–Z letters; stored score history is retained. Leaderboard reads resolve `username`, `playerName`, legacy `initials`, `player`, or `name` fields without detaching a label from its score. Firestore REST supplies anonymous reads for levels, scores, community maps, and public profiles.
- **Bundled campaign data**: `_manifest.json` contains the 11 replacement boards, all available offline; the production Firestore campaign mirrors the same IDs and content so connected and offline play remain consistent.
- **Community feed**: REST projection of 25 summary documents ordered by updatedAt and document ID. Selected boards and visible thumbnails use the existing full-document cache. Publishing adds bounded preview points. Loading, empty, retry, and load-more states stay scoped to Community; stale destination responses cannot replace another screen. This is pagination and search of loaded entries, not global full-text search.
- **Ranked score metadata**: Plausibility bounds depend on peg count. New clients include ruleset/time-limit/level timestamp; the server validates these and records a SHA-256 revision. Old clients remain bounded and are marked legacy. This is not authoritative replay verification; existing standings are retained.
- **Backend**: Firebase project `freeballing-59589`; callable Node.js 22 functions verify Firebase Auth, derive owner UID and username server-side, validate and rate-limit writes, and transact scores, votes, levels, and username claims. Firestore client writes are denied; public documents contain no private Google identity.
- **Guest policy**: Guests retain all gameplay, local-save, settings, and offline features, plus the full editor on desktop. Cloud score submission, community voting, community publishing, and cloud deletion require an authenticated account; score/publishing also require a public username.

## Network

- `INTERNET` and `ACCESS_NETWORK_STATE` enabled for leaderboards and community levels
- Offline play uses bundled level JSON under `data/levels`
- Firebase App Check remains staged in observation mode; enforcement is not part of this client release
